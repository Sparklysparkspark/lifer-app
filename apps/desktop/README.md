# Lifer desktop

The desktop app: a React/TypeScript frontend (`apps/web`) running inside a Tauri shell, with
the same Fastify API (`apps/api`) bundled as a sidecar process talking to a Postgres instance
embedded via `postgresql_embedded` (see `src-tauri/src/embedded_db.rs`), so it runs standalone with no
separate Docker or Postgres install.

## Development

```bash
npm start -w desktop     # tauri dev: hot-reloads the web frontend against a local API
```

See the repo root [CONTRIBUTING.md](../../CONTRIBUTING.md) for the full local setup (Postgres,
migrations, seeding).

## Building a release

```bash
npm run dist -w desktop
```

This chains several steps (see `package.json`'s own `dist` script and `scripts/`):

1. `npm run build -w web`: builds the frontend.
2. `prepare-resources.js`: stages the API + its dependencies as bundled resources.
3. `fetch-node-sidecar.js`: downloads a vendored Node runtime to execute the API sidecar with,
   and fails the build if it doesn't match nodejs.org's `SHASUMS256.txt` for that release.
4. `fetch-catalog-seed.js`: downloads the pre-built species/region catalog every fresh install
   restores on first launch, plus its manifest. Verifies the manifest's sha256 when present and
   fails the build if the seed is over 200MB.
5. `tauri-build.js`: the actual Tauri/Rust build, producing a platform-native bundle.
6. `resign-macos.js` (macOS only): re-signs the bundle and patches `Info.plist` with the
   folder-access usage descriptions macOS requires before it'll prompt for Desktop/Documents/
   Downloads access at all. Signs with `MACOS_SIGNING_IDENTITY` (release CI sets it to a
   self-signed "Lifer" certificate), or ad-hoc (`-`) when that's unset.

`scripts/headless-postgres.js` is a separate utility for running the embedded Postgres instance
standalone (start/stop/status), independent of the GUI app being open. Useful for background
maintenance jobs against the same database. It reads the per-install database password the app
writes to `app-data/postgres-password` (mode 0600) on first launch.

Release builds ship without devtools (debug builds from `tauri dev` always have them). For a
release build with devtools, pass `--features devtools` through `TAURI_BUILD_ARGS`.

A connected server's pages get IPC access only for the origins saved in the desktop config; the
grant is added at runtime in `lib.rs` (`grant_remote_capabilities`), not in `capabilities/`.

Directories you don't need to hand-edit: `src-tauri/target/` (Rust build output),
`src-tauri/resources-staging/` (files staged by `prepare-resources.js` for bundling),
`src-tauri/binaries/` (the vendored Node sidecar). All gitignored, all regenerated by the
build steps above.
