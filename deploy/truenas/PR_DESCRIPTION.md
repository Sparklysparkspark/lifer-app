## Description

Adds Lifer to the community train.

Lifer is a self-hosted photo archive and life list for wildlife photographers. It organizes a
photo library around species, taxonomy, locations, dates and trips, and keeps a life list and
regional checklists from the photos you have actually taken.

The app runs the Lifer server (web UI and API on one port) with a Postgres 18 database. It only
needs the `pgcrypto`, `pg_trgm` and `unaccent` extensions, so it uses the stock `postgres` image
through `deps.postgres`. The server runs as any non-root user (568:568 by default).

- First-time setup: the first person to open the web UI creates the account. There is no setup
  code, so open it right after installing, before exposing it outside your network.
- Photos go in **Data Storage** (`/data`). **App Data Storage** (`/app-data`) holds thumbnails,
  previews and optional downloads (species matching models, offline map), all of which Lifer can
  rebuild or download again.
- Each **Additional Storage** mount path is passed to Lifer as a library folder
  (`LIFER_LIBRARY_ROOTS`), since Lifer refuses paths outside its library folders.
- **GPU Configuration** is optional and only applies to the lifer container. Lifer tests an
  assigned NVIDIA, Intel or AMD GPU once and uses it for species matching only if it gives the
  same results as the CPU and is faster, so leaving it unset changes nothing. For NVIDIA it
  downloads the CUDA libraries it needs (about 1.5 GB) into App Data Storage; nothing
  GPU-specific is in the image.
- No email and no other settings: a forgotten password is reset with `lifer-admin reset-password`
  from the lifer container's Shell. Lifer decides per request whether the login cookie is HTTPS
  only, so it works over plain http and behind a TLS proxy alike.
